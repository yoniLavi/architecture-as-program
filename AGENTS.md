# Architecture as Program — Notes for all Agents (This AGENTS.md is also symlinked for Claude Code to access as CLAUDE.md)

## What this repo is

A longitudinal research program arguing that AI coding agents + functional reactive programming + object-capability security converge on a new development paradigm: the **signal graph** as simultaneously architecture model, security policy, and source of truth.

It is structured as a **corpus of papers backed by a shared, evolving research artifact** (see `papers/README.md` and `METHODOLOGY.md`):

- **Paper 1 — the founding vision** (`papers/01-vision/`) is **frozen** and stands alone as a self-contained vision paper (dated *June 2026*, before the executable demonstrator `poc/` existed; it does **not** reference Paper 2). It is **published** as a Zenodo preprint ([doi:10.5281/zenodo.21473361](https://doi.org/10.5281/zenodo.21473361), CC BY 4.0, 21 July 2026). Its single sanctioned publication revision is **spent**: a July 2026 preparation step (typos, phrasing, removal of one proof-of-concept-preview passage so it stands alone; **no prediction or argument changed**) and a 21 July concluding step at the publication event (DOI + licence stamped on the title block, one Figure 1 legibility fix), both recorded in `ERRATA.md`, after which it was **re-frozen at the published commit** — where `scripts/check-freeze.py`'s `FREEZE_REF` now points. It carries its own pinned graph/diagram inputs and is **permanently errata-only** — do not edit it; the freeze guard fails the build if it drifts. It is also **marked published** (`papers/01-vision/PUBLISHED.json`, since 28 Sep 2026), so it is **served, not built**. `make` copies `papers/01-vision/published/`, which holds the Zenodo PDF byte-for-byte plus web copies and figures frozen once. No change to the Lua filter, CSL, `citations.bib`, or typst/pandoc versions can reach it, and the freeze guard checks every served file's checksum. Never regenerate those files as a side effect. Re-rendering them is a deliberate, author-approved act recorded in `ERRATA.md`, with the checksums updated in the same commit.
- **Paper 2 — *Confinement by Construction*** (`papers/02-demonstrator/`) is the one **living** paper: it builds from the shared root artifact, reports what that artifact establishes, and accounts for Paper 1's predictions against it (§5). Its lead claim is that a node's `with` clause *determines* its compiled component's import surface, derived from the graph and checked against the binary. Its Zenodo DOI, **10.5281/zenodo.23057135**, is reserved and stamped, and the record is not yet published.

  **Paper 3 is the next paper, and is not yet written.** The ordinal was once held by another: a separate method paper, *Predicting Before Building*, existed from August to September 2026. It was merged into Paper 2 on 30 September 2026 (`openspec/changes/archive/2026-09-30-merge-and-condense-papers`), because Paper 2 cited it while it was unpublished and it cited Paper 2 for every figure, so neither could publish first. Its last text is at the git tag `paper-3-before-merge`. The ordinal 3 was retired at the merge and **reclaimed by the author on 10 October 2026**: the next paper — the one the feed-triage service and the generation experiment are evidence for (`docs/ROADMAP.md`) — is **Paper 3**, and will live at `papers/03-…/`. So "Paper 3" means two things by date. In anything written before 10 October 2026 — the tag `paper-3-before-merge`, the archived changes, and the change `build-feed-triage-and-generation-experiment`'s first commits, which say "Paper 4" for the new one — read it by its date; in new writing, call the merged one **the former method paper**. The rule that came out of the merge: **a published paper cites no unpublished work.**

This is primarily a **writing project**: the papers are the outputs that matter. But they are backed by a real, tested toolchain (below), not vapourware.

## The living paper's structure

**Paper 2 — *Confinement by Construction*** is in **paper form**: it reports a built artifact, it does not propose one. The arc:

1. **Introduction** (§1) — The window (agents removed the human objection to graph representations), the **central claim** — led by capability-surface derivation, with the trust lattice second — and five contributions, the last being the accounting
2. **Design** (§2) — FRP extended, the signal graph, the concrete graph (§2.3), security properties (§2.4). Inherited from Paper 1, cut to what §3–§4 depend on; **this is where hedging is most at risk**, because it describes intent, not artifact
3. **Implementation** (§3) — The six validator analyses (§3.1), the two enforcement tiers (§3.2.1, the confined tier, is the paper's lead result), then §3.3 "Also built": identity/revocation/principal, sub-graph execution, contracts, and the execution trace — which also carries the inspector's one-sentence mention
4. **Evaluation** (§4) — The graph-to-binary derivation **first**, because it is the lead claim, then corpus verdicts, boundary overhead, prompt-injection attenuation, host vs confined tier. **Every figure is interpolated from `dist/evaluation.json`** — never hand-type a number here, *including counts of things in the data* (a hand-typed "the two mutations" has already drifted once)
5. **Predictions and outcomes** (§5) — The protocol in brief (§5.1), `tab:outcomes` with every prediction of Paper 1 and its verdict, and the two corrections building forced (§5.2), with two apparent corrections noted there and deliberately not counted: the trust-lattice unification, a simplification (the pre-freeze validator's separate rules already caught the laundering graph), and the `ServiceOutcome` boundary check, an implementation gap (the artifact keeps the vision's union convention; only the demonstrator's unresolvable alias was unchecked; reclassified by review on 30 September 2026). **The table is data** (`#let outcomes` at the top of the file), and the verdict counts in the abstract and conclusion are computed from it with `verdicts(...)`. Never type a count of verdicts by hand
6. **Related work** (§6) — §6.1 is LLM-agent security (CaMeL, TACIT, language-based agent control, AgentDojo, the pattern catalogue) and is load-bearing: any prompt-injection claim must position against it
7. **Limitations and open problems** (§7) — Construct, internal, external, and security-argument limits, threats from the method (§7.5), then §7.6, the open problems that bound *these* results
8. **Future work** (§8) and **Conclusion** (§9)

Technical Note A and Annex B no longer exist in Paper 2 (Paper 1 still has both — it is frozen).

## When editing the proposal

"The proposal" below means **Paper 2** (`papers/02-demonstrator/proposal.typ`). Paper 1 is frozen — never edit it; corrections go in `papers/01-vision/ERRATA.md`.

**Demos get a mention, never a section.** Visual demos (the `ui/` inspector, and successors) are built to the repo's usual evidence discipline and are worth building — they bring attention to the programme. But in the papers they are one to three sentences plus at most one figure, folded into the section covering the underlying artifact, absent from the contributions list, and they never move a verdict in §5's accounting: a verdict follows the underlying capability, not the demo that partly exercises it.

- **Maintain hedging on unproven claims.** The type system does not exist yet. Claims about properties it would provide use conditional language ("would be inexpressible", "in a well-typed realisation", "in a sound realisation of the type system"). Do not strengthen these to present tense without an implementation to back them. Two traps specific to Paper 2's form: (a) it reports a built artifact, so the surrounding prose is in the present tense and an unproven claim reads as substantiated unless its mood is *deliberately* kept conditional — §2 (Design) is where this fails; (b) a property that holds only on the **confined tier** must say so, or it reads as universal when the host tier demonstrably escapes. **Length work is never paid for out of qualification**: where a rewrite cannot hit a word target without weakening a hedge, the hedge wins and the target is missed.
- **Part of that is now checked, and most of it is not — know which.** `scripts/check-hedges.py` pins, verbatim, passages of Paper 2 §2.3 and §2.4 (`sec:concrete-graph`, `sec:security`) in which an unproven claim and the qualification bounding it appear *together*, and fails the build if one goes missing. Because claim and hedge are pinned as one fragment, a rewrite cannot shed the hedge and keep the claim, and rephrasing the claim also fails — forcing a deliberate re-seed, the same way widening the overhead band is an edit to a claim rather than a tuning knob. **It is a regression guard over the passages it pins and nothing more.** It cannot tell that the pin set is complete, cannot tell that a hedge qualifies the right claim inside a fragment, and its pins are hand-maintained, so a wrong pin is as invisible as a wrong row in the derivation's mapping table (§7.1 admits the same about itself). Everything outside the pinned passages — the whole of §2.1 and §2.2, the design preamble, and every conditional claim elsewhere in the corpus — **rests on review, not on a check**. No paper should describe the guard as more than this; it is repo process, not evidence, and belongs in no paper at all. Re-seeding a pin is a deliberate act: say so in the commit message.
- **A claim that *understates* the artifact is drift too, and only review catches it.** The evaluation harness guards the overstating direction (a paper cannot claim what the artifact cannot do); nothing guards the other way. Seeding the hedge pins in August 2026 found three passages (§2.3, §2.5 twice, in August 2026 numbering) still calling the principal binding "undesigned" after §3.4 had built, propagated, and tested it — what is actually open is binding it to a handle, and typing it (in the event, a later review on 30 September 2026 found the principal is only recorded and propagated, bound to no handle: the correction had overshot the other way). When a change lands a capability, sweep the design sections for prose that still says the artifact lacks it.
- **Never hand-type an evaluation figure.** §4's numbers come from `dist/evaluation.json` via `#ev`/`#d` interpolation. If a figure needs a new form, add it to `serialise()` in `poc/evaluate.py` (`display` holds pre-formatted strings, because typst and pandoc format the same float differently).
- **Keep citations accurate.** Every factual claim about prior work should be traceable to a citation. If adding a new claim, add the citation. Run `make build` to catch broken references (typst will error) and `scripts/check-citations.py` to catch orphaned bib entries.
- **Preserve the argument arc.** Each section builds on the previous. New content should slot into the existing structure, not break the flow.
- **Concrete over abstract.** The proposal's weakest mode is unsupported generality. Prefer specific examples (like the `CustomerSupport` graph or the `Untrusted<UserMessage>` type error) over sweeping claims.
- **Acknowledge limitations honestly.** Paper 2 §7 exists for a reason. If a new claim has an honest limit on what the artifact shows, name it there; if it has an open problem that bounds the claim, name it in §7.6; if it belongs to the forward programme rather than to this result, it goes in §8 (Future work), which is deliberately short.
- **Keep it tight — say each thing once.** Each load-bearing point has one primary home and is cross-referenced elsewhere, not restated (the free-text residual lives in §4.4, the trust-lattice mechanism in §3.1, the `unknown-unknown` ambient-authority argument in §3.2.1). When adding material, extend the primary statement or reference it; do not reintroduce a second full explanation. Length is a target, not a quota — never cut a stated limitation, a hedge, or the predictions-and-outcomes table to hit a page count.
- **Length: ~10,000 words (~28pp) after the September 2026 merge, now ~12,900 (~32pp) after the review rounds of 30 September (A–N; the §5 accounting grew to 24 rows when checked against Paper 1's text) — over the approved ~12,000-word budget.** The rounds' growth was almost all disclosure of limits review found in the artifact (it went to §3, §4 and §7), and the budget is now close: the next addition should be paid for by dropping scope, not by shaving a hedge. Three tightening passes in August 2026 recovered only ~315 words from a 42pp Paper 2, and the reason still holds: **hedging is a per-claim tax that "say each thing once" cannot collect against.** The free-text residual is stated in §2.3, §2.4, §4.4 *and* §7.4, because each bounds a *different* claim, and the hedge rule wins that conflict. So is its sibling limit, **trust enters only where it is declared** (§1.1, §2.1, §2.4, §5.1, §6.1, §7.4): what a handle returns is unlabelled, so retrieved content — indirect injection — is invisible to the lattice unless a node's output type says `Untrusted<_>`. What did shrink the paper was the author's scope decision on 30 September 2026: merge the method paper in, and condense both from ~27,000 words to ~10,000 (FRP history to a paragraph, one illustration and the corpus-relation section dropped, Paper 3's phase-by-phase agenda reduced to §8). No hedge pin needed re-seeding. The budget per section is in `openspec/changes/archive/2026-09-30-merge-and-condense-papers/design.md` (archived 30 September 2026, before publication). Two lines ran over, "Also built" (§3.3) and Design, both because the limits each carries stayed whole. **If length must fall further, the lever is still dropping scope, not shaving prose** — raise it with the author.

## Tooling (present and tested)

Although this is a writing project, the paper ships with a working, tested PoC toolchain — it is what Paper 2's §3 (Implementation) and §4 (Evaluation) report. It is not vapourware: it builds and passes its tests on every commit (via the pre-commit `make-build` and `pytest` hooks) and in CI.

- **Canonical graph sources** — `graphs/*.json` are the single source of truth. `graphs/schema.json` is the JSON Schema they validate against; `customer-support.json` and `support-platform.json` are the two graphs rendered in the proposal. Pseudocode listings *and* SVG diagrams are generated from them (`scripts/generate-graph.py`), so the figures cannot drift from the text.
- **Type parser** — `scripts/type_parser.py` parses the capability-annotated type grammar (angle-bracketed generics, capability scopes/modes, sum types with role labels). `scripts/emit-grammar.py` emits `dist/grammar.md` from it, so the documented grammar is generated from the implementation, not maintained by hand.
- **Graph validator** — `scripts/graph_validator.py` (driven by `scripts/validate-graphs.py`) runs the six classes of analysis described in Paper 2 §3.1: edge type-compatibility (data-shape match with sum-variant resolution), trust-lattice checking (a two-point `Untrusted ⊑ Trusted` lattice with no upward coercion, checked on every edge *and* node body — per variant of a sum and through type constructors, since an adversarial review on 30 Sep 2026 found `launder_trust` passing when one output variant was marked untrusted (now the pinned corpus case `launder_trust_via_variant`), and a composition boundary keeps trust in its output check; a **sink rule** beside the order keeps a node holding a tool-scoped `LLMClient<[...]>` from consuming `Untrusted<_>` or being declared a discharger, because the lattice alone constrains raising trust, not consuming it (and a tool client may not be routed into a sub-graph's inference-only slot, where the rule would not see it); laundering through an *undeclared* node is one lattice violation, laundering by declaring the consumer a discharger is caught by the sink rule; the harness pins each reason class by its own check's message, *present* rather than unique, so the sink rule cannot mask a lattice that stopped firing (it once did); `discharges_trust` marks the sole node licensed to raise trust — trust laundering is now one lattice violation, not a rule beside edge typing), variant completeness, capability narrowing at composition, intra-graph consistency (which also rejects a capability type in any data position, so no handle travels on an edge), and cross-graph signature matching.
- **Executable runtime** (`poc/`) — loads the same graph JSON, instantiates each node with **injected capability handles**, and propagates signals. Reuses the validator to reject unsafe wiring at assembly time. Ships a prompt-injection demonstration (`uv run python -m poc.demo`, `--live` for real Claude calls). See `poc/README.md`. Runs each node on one of two **enforcement tiers**, and reports which ran each node.
- **Structured execution trace** (`poc/trace.py`) — **two layers, one derived.** A `Call` is a per-use record (interface, instance, operation, sequence index) in encounter order; a `Crossing` is `(interface, instance)` deduplicated and is *computed from* the calls, not recorded beside them. That projection is what makes the two tiers' traces structurally equal — the host tier calls once where a confined component loops internally — so the tier-equality test is now a property of the projection rather than a coincidence between two hand-maintained views, and the call layer is **excluded** from structural comparison because the tiers ought to differ there. Also records the acting **principal** and delegation chain (RFC 8693 shape) where a run binds one, and per-node input/output **trust labels**. Sub-graph runs nest. Pinned by a committed JSON Schema (`poc/trace-schema.json`) and deterministic. Two limits stated in the docstring and the paper, not just here: the call layer carries ordering and multiplicity but **not values**, so it is still insufficient for replay; and on the host tier it is as circumventable as everything else host-tier, so it is confined-tier-authoritative and host-tier-advisory.
- **Hierarchical composition, operational** — a node whose name resolves to another graph is a **sub-graph node**: the runtime executes it by nested `assemble` + `execute`, so composition adds no second execution model. `SupportPlatform` now *runs*, not merely assembles: a customer request goes `RouteRequest` → `CustomerSupport` (the nine-node graph, one level down) → `RecordAudit`. Four properties, all tested: (1) **a sub-graph cannot provision authority of its own** — `execute` holds no backend, so the child gets exactly the handles the parent routed and nothing else — **unattenuated**: a wider handle the validator accepted as narrowing reaches the child whole, since narrowing is checked, not enforced (Paper 2 §7.6); confinement across the boundary falls out of the plumbing rather than a rule; (2) **identity routing has an executable consequence** — the `customer_session` instance the platform declares for `CustomerSupport` is the one the reply node *inside* it sends on, and its sibling's is untouched; (3) the parent matches the child's flat parameter list **by position** (routing option (i) of the research agenda — settled at the runtime; options (ii)/(iii) stay open); (4) **composition crosses tiers** — severing a routed instance at the parent makes a confined crossing fail two levels down. **Composition is checked before it runs** (30 Sep 2026): `assemble` validates a graph together with every canonical graph it reaches, `_run_subgraph` re-validates a parent against a caller-supplied child and refuses a child whose name differs from its node's, graph names must be unique in a batch, and no graph may contain a node of its own name — each collision used to skip the cross-graph checks, and adversarial review ran compositions the validator rejects through all of them. Bounded on purpose: only leaves on the taken path have impls (`AgentDashboard`/`BillingService` are neither graphs nor registered, so those branches don't run), and a run reaching **several** terminals is refused rather than guessed (the open aggregation question). The boundary output is the **union of the sub-graph's terminal types**, spelled out (`DeliveryConfirmation | EscalationTicket`) rather than named, because the language has no alias mechanism — `ServiceOutcome` survives only as the Python-side alias in `poc/values.py`. The fix is **structural, not nominal**: the cross-graph analysis requires a sub-graph node's declared boundary output to *equal* the union of the referenced graph's terminal outputs, so a node narrowing it (claiming only `DeliveryConfirmation`, hiding the escalation path) is rejected at validation with every edge still type-checking. Pinned by the `mislabel_subgraph_output` corpus case and its reason class.
- **Two enforcement tiers** — the **host tier** (default) is host-discipline: a node receives only its declared handles, each scoped by its type, but nothing stops a hostile Python node from `import os`. The **sandbox tier** (`poc/sandbox/`) compiles node bodies to WASM **components** (Rust + `wit-bindgen` → `wasm32-unknown-unknown` → `wasm-tools component new`) and runs them under `wasmtime`. Each capability kind is a **typed WIT interface** (`poc/sandbox/wit/caps.wit`), so a node's `with` clause *is* the set of interfaces its component imports. A **hostile-node suite** (`tests/test_poc_sandbox.py`) asserts that filesystem/network/env escapes *succeed* on the host tier (the gap, recorded as a test) and *fail* on the sandbox tier, each denial pinned to its discriminating error ("not supported on this platform"; env "not found" while the variable is set). The evaluation harness's tier table (`probe_escapes`, pinned by `check_escapes` in the build) adds the host-tier minting of ungranted handles and the clock/HTTP rows. The host column is plain Python in the runtime's own process — where a host-tier body runs — not a node executed through `assemble`/`execute`. The two tiers **compose** in one graph (the migration story). Enforcement is unforgeable at the WASM boundary, **not** at the memory level — CHERI remains a named follow-up. Build the artifacts with `make wasm` (needs a Rust toolchain, `rustup target add wasm32-unknown-unknown`, and `wasm-tools`); the built components are committed under `poc/sandbox/wasm/` so tests run without either toolchain. **The engine is sized for many short-lived stores** (`engine_config()` in `poc/sandbox/host.py`: 32MiB reservation, 64KiB guard, `memory_may_move`). wasmtime's defaults — a 4GiB reservation plus a 64MiB guard — assume a few long-lived guests, but this tier builds a *fresh store per node invocation*, so it was asking the OS to reserve 4.06GiB every time; on a loaded machine `mmap` refuses and the tier stops instantiating. The cap is ~100× what any node here uses and the crossing measurement is unmoved by it. Two rules follow: **the benchmark must build its engine from the same config** (or it measures a tier nobody runs), and **a resource failure must not be reported as an ungranted capability** — both failures land in the same handler, and misattributing the first sends a reader hunting a security fault that isn't there.
- **Why the boundary is typed, and why `unknown-unknown`** — two properties follow, and both are asserted in tests rather than in prose. (1) **No ambient authority at all**: an earlier `wasm32-wasip1` version was confined by an *empty WASI context*, but its modules still *imported* `fd_write`/`environ_get`/`path_open` — powerless, yet present, so confinement was a fact about the host's configuration. Components built for `unknown-unknown` with **no WASI adapter** do not import them at all (`wasi_imports()` returns `[]`; the ambient-escape hostile component (`hostile_ambient`) imports only the function-free `aap:caps/types` vocabulary). A `wasip2` build would reintroduce this via `wasi:cli/*`. (2) **The boundary cannot drift from the graph**: `poc/sandbox/interfaces.py` *derives* each node's expected interface set from its `with` clause in the graph JSON (via `type_parser`), and a test compares it against the built component's actual imports — an over-granting world fails the suite. Typing also absorbed two node-body checks into types: `intent` is a WIT `enum` (the closed set is now unrepresentable to widen, so the old membership check is gone) and the model's reply is a WIT `variant` (a malformed reply has no encoding). (3) **The vocabulary now spans seven kinds** — `LLMClient`, `DBHandle`, `ResponseChannel`, `EventEmitter`, plus the I/O kinds `Clock`, `HTTPClient<[allowlist]>`, `Notifier<'channel'>` added ahead of the feed-triage toy. `Clock` is granted as upstream `wasi:clocks/wall-clock` *directly* (WIT vendored under `poc/sandbox/wit/deps/clocks/`), which sharpened the definition: "ambient" means *an import the `with` clause did not grant*, not "anything wasi-namespaced" — `wasi_imports()` is vocabulary-level and so cannot see a clock on *any* node; the per-node check is `ungranted_imports(component, granted)`, which reports a granted clock clean and an ungranted one flagged (tested), and the evaluation's ambient figures use it. The HTTP allowlist lives in the *handle* (host-side), narrows by set inclusion at composition — **checked at validation, not enforced**: the runtime routes the parent's handle to a sub-graph unattenuated, so a child declaring a smaller allowlist can use the parent's — and an off-list request is refused at the crossing exactly like an out-of-scope tool call. Exercised by `node_heartbeat` (all three kinds in one confined body) and `hostile_clocked` (clock-only, escapes still denied); neither is in a canonical graph yet — the feed-triage graph is proposed separately.
- **Evaluation harness** (`poc/evaluate.py`) — runs the demonstrator's own evidence and emits **`dist/evaluation.md`** on every build, the way `dist/grammar.md` is emitted from the parser: the **graph-to-binary derivation** (per ported node: the interface set derived from its `with` clause vs what the built component imports — the lead claim, reported as a figure and not only asserted in `test_poc_sandbox.py`; it also carries one row from `FEED_PULSE_GRAPH`, which does not ship, because that is what puts the three I/O kinds through the gate, and rows are marked shipped vs not. **Coverage is reported as `kinds_covered`, computed from the rows — never as `len(CAPABILITY_KINDS)`, which is the size of the mapping table and states what the derivation *could* map rather than what it has been held against a binary for; `EventEmitter` is currently mapped but unexercised, and the paper says so**), the graph-mutation corpus, the overhead measurement, and the prompt-injection outcome on both tiers, consolidated into one artifact a paper can cite. An over-granting *or* under-importing component fails the build here, not just in the suite. Because every reported row necessarily agrees, the gate is also shown **rejecting a real binary**: `NEGATIVE_CONTROLS` holds `hostile_ungranted` (built with `ParseMessage`'s signature plus a `kb-read` import) to `ParseMessage`'s clause and pins it to be caught for exactly that interface — a gate that stopped firing fails the build. It *imports* the corpus/bench/demo rather than re-deriving them. Crucially it is a **regression guard, not a report**: each corpus case pins the verdict it must produce *and the reason class it must be caught by* (`launder_trust` must be caught by the trust lattice, not as an edge type mismatch — a pass/fail pin would stay green if that regressed), and any divergence fails the build without rewriting the artifact. The corpus pins itself against silent growth too: adding an `UNSAFE_VARIANTS` entry without pinning it is an error, not an uncounted pass. The canonical graphs are corpus cases in their own right — a validator that rejected everything would catch every unsafe wiring and be worthless. The artifact states that the corpus is **curated and illustrative** (counts, not a soundness claim) and reports the host tier's escapes as the recorded gap beside the sandbox tier's confinement. This is the one build step that is **not** stdlib-only: it needs `wasmtime`, so `make build` runs it via `uv run --group poc` (installed on demand; no CI change needed).
- **Overhead measurement** — `poc/sandbox/bench.py` (`uv run --group poc python -m poc.sandbox.bench`) reports component compilation, per-node instantiation, and per-capability-crossing cost against the envelope stated in the paper. Current numbers: a crossing costs **tens of µs** (~25µs; well inside the <1ms envelope) *even though every crossing now lifts/lowers typed WIT values*; instantiation tens of µs; compilation a one-time cost of a few ms wall-clock, which reads as tens of ms in the process CPU time now reported (it sums wasmtime's compile threads). **Do not compare these to the pre-component figures**: the benchmark's timing loop was fixed at the same time (it now warms and takes the best of several rounds; it previously timed a single cold pass, which charged JIT warm-up to whatever it measured first — and since the crossing cost is a *difference* of two timings, that could distort it by an order of magnitude). No like-for-like flat-ABI measurement exists (the old figure came from the cold-pass loop, which could be off by a decade either way), so the only supported claim is that the typed crossing sits inside the envelope — not what typing it cost. **The figure is pinned to a band** (`CROSSING_BAND_MIN_MS`/`MAX_MS` in `poc/evaluate.py`, 5–100µs): correcting the timing loop bounded the cold-pass fault but did not remove the fragility, and a contended machine still differences its way to a figure a decade too large — one build wrote **343µs** where the same code writes ~25µs, and nothing caught it because `within_envelope` (<1ms) passed. `measure_within_band()` re-measures a transient excursion and a sustained one fails the build. **Timings are CPU time, not wall-clock time** (since 29 October 2026; the author: "there is no idle machine here"): the measuring thread's for calls into a component, the whole process's for compilation (wasmtime compiles on worker threads, which thread time would miss: 1.1ms against ~31ms). On a loaded machine that took the crossing from ~80µs wall to ~50µs CPU, not to the quiet ~25µs: CPU time removes queueing, not contention, so the band stays. `tests/test_poc_bench_clock.py` pins the clocks. The ceiling is a decade boundary and the band half-open there, so a measurement that passes names single-digit or tens of microseconds, never hundreds; the paper interpolates whichever it is. **Never hand-type that magnitude in a paper either** — "tens of microseconds" is a claim about the measurement exactly as "25µs" is; use `#d.crossing_magnitude`, which `serialise()` derives from the same run.
- **Graph inspector** (`ui/` + `poc/inspector_api.py`) — a web inspector reported in Paper 2 §3: renders the canonical graph JSON served **byte-for-byte** (a contract test pins parity), executes runs server-side through the same `assemble`/`execute` path as the tests, and overlays the returned trace (per-node tier, edge trust labels, crossings with instance names, nested sub-graph drill-down). The evaluation corpus's mutation cases are runnable and display the validator's rejection with its **pinned reason class**; a guided prompt-injection walkthrough mirrors §4.4's language (attenuation, not elimination; host tier = shape, not enforcement). It is an **inspector, not the predicted visual editor** — §5's verdict is *not attempted* (an earlier draft's *partial* was the demo flattering the prediction), and authoring (validator-in-the-loop editing) is future work (§8); never let paper prose upgrade this. Claims discipline: every paper-asserted behavior maps to a Python contract test (`tests/test_poc_inspector_api.py`) or a Playwright e2e check (`ui/e2e/`); the e2e run regenerates the committed `ui/screenshots/*.png`, which `make build` copies into `dist/ui/` for the paper figure with plain `cp` — **Node is never needed by the corpus build** (verified by building with `node`/`npm`/`npx` shimmed to fail). Run with `make ui` (API + dev server), check with `make ui-check` / `make ui-e2e`.
- **Tests** — `tests/` is a pytest suite covering the parser, the validator, the runtime, both enforcement tiers, the execution trace (`test_poc_trace.py`), the evaluation harness, the inspector API's contract (`test_poc_inspector_api.py`), the hedge guard's failure path (`test_check_hedges.py`), the freeze guard's, including that its reference is reachable from HEAD (`test_check_freeze.py`), and the pandoc cross-reference filter (`test_resolve_crossrefs.py`, skipped without pandoc): **707 tests + 21 subtests, all passing** as of 9 October 2026 (`make test` or `uv run pytest`; run with `--group poc` to include the sandbox-gated tests, which otherwise skip — most of `test_poc_sandbox.py`, `test_poc_evaluate.py`, `test_poc_feed_sandbox.py` and `test_poc_evaluate_feed.py`). 295 of them arrived with the feed-triage service and the generation experiment: the I/O capabilities, the feed parser, fan-in, the driver, the CLI backend (against a fake executable), the generative contract mode, the generation harness, and the feed evaluation. The validator and parser stay dependency-free so the pre-commit hook remains portable; the runtime's optional dependencies (Anthropic SDK for `--live`, `wasmtime` for the sandbox tier) live in the `poc` dependency group (`uv sync --group poc`) and must never leak into `scripts/` — which is why the evaluation harness lives in `poc/`, not `scripts/`.
- **Build outputs** — `make build` produces the whole corpus under `dist/papers/<id>/proposal.{pdf,md,html}` (each with the figures it references), the shared rendered graph/diagram SVGs, `dist/grammar.md`, `dist/evaluation.md`, and deprecated `dist/proposal.{pdf,md,html}` aliases to Paper 2 for one link-migration transition. Each paper's PDF is also emitted under its citable publication name (`lavi-<year>-<slug>.pdf` — Paper 1: `lavi-2026-architecture-as-program.pdf`, published; Paper 2: `lavi-2026-confinement-by-construction.pdf`, year provisional until it publishes); that copy is what gets uploaded to venues, while internal names stay `proposal.*`. `dist/` is gitignored. Living papers reference the shared figures root-absolutely (`/dist/...`, compiled with `typst --root`); the frozen paper reads its own figure tree through the committed `papers/01-vision/dist` symlink.
- **Citation hygiene** — paper-aware. `scripts/check-citations.py` treats a bib entry as used if *any* paper cites it (over the shared `citations.bib`); `scripts/validate-bib.py` is available for manual checks (it runs in neither the build nor CI, and its fuzzy matching can fail on noise). Every citation must resolve (Typst errors on broken refs per paper). `scripts/check-freeze.py` guards the frozen paper against silent edits (its sources against the freeze commit, and its served artifacts against `PUBLISHED.json`), and `scripts/check-hedges.py` guards the living papers' pinned unproven claims against losing the qualification that bounds them — a regression guard over the passages it pins, not over the discipline (see "When editing the proposal"). Both run in `make build` and pre-commit; the hedge guard is stdlib-only, like the validator, so the hook stays portable.

### After Paper 2: the feed-triage service and the generation experiment

Built by `openspec/changes/build-feed-triage-and-generation-experiment` (October 2026, still open: live operation and routing-point attenuation remain). **None of this is in Paper 2, and none of it may move a Paper 2 figure**: `tests/test_paper2_figures_pinned.py` holds every non-measurement key of `dist/evaluation.json`, and the five inspector screenshots by hash, to their values before this work began. Re-seed that pin only for a deliberate Paper 2 revision.

- **Paper 2 counts a frozen vocabulary.** `StateHandle<'name', read|read-write>` is an eighth capability kind (two WIT interfaces, `state-read` and `state-rw`). `poc/sandbox/interfaces.py` keeps `PAPER2_KINDS`/`PAPER2_INTERFACES` beside the full sets, and `poc/evaluate.py` reads the `PAPER2_*` ones. A kind added for a later artifact goes in the full sets only.
- **Fan-in exists in two restricted forms, and no others.** A *per-item map* (`"each": true` on a sub-graph node: one isolated child run per list element, checked element-wise, trust label included) and a *positional join* (`"to_input"` on edges: one edge per position, run once, values by position). Ready nodes run in an order fixed by the graph's shape, so a trace does not move with edge listing order. A second arrival at one input — merging streams — is still refused. A join across mutually exclusive branches is rejected at validation; one that merely did not fire fails the run.
- **`World`** (`poc/handles.py`) is what outward-facing handles are bound to: live HTTP or canned, file-backed or in-memory state, a publishing notifier. The default binds nothing real, which is what every test runs in. Live `HTTPClient` applies its allowlist to every redirect hop, with a 5MiB cap and a 15s timeout; `fetch` returns transport failures (and a refused redirect) as values, while a request the *node* makes off its allowlist raises.
- **The validator has no opinion on where a graph fetches.** The service's security argument (one node holds HTTP, no model upstream of it, fetched content labelled `Untrusted<_>`) is checked by `poc/feed_policy.py`, a check written for this service and run by the driver before every tick. The feed corpus pins two rewirings the **validator accepts** and only that check rejects. Never describe this as a validator analysis.
- **`ClaudeCLIBackend`** (`poc/llm.py`) calls the logged-in `claude` CLI: `--tools "" --safe-mode --no-session-persistence`, an empty working directory, `ANTHROPIC_*`/`CLAUDE*` scrubbed from the environment (an API key would be billed in preference to the subscription), and a usage ceiling that refuses further calls. **No test or build step calls a model.** *Paid APIs (policy since 29 October 2026; it was "none" before):* do as much as possible on the subscription already paid for. Spend on a paid API (for example DeepSeek, a cheap, strong second model family) only once the approach is validated and the extra testing has earned it. Each spend is approved by the author first, kept small, and recorded. Keys come from the environment and are never committed.
- **The hostile-feed corpus** (`poc/feeds/corpus/`) runs eleven feeds through the whole service on both tiers against `FooledModel`, a stand-in that obeys every instruction it is shown. Each case is pinned to `impossible`, `bounded` or `residual` — and **the residual cases are pinned as succeeding**. Do not let prose turn a green build into a claim that the digest cannot be made to lie.
- **The generation experiment's rules.** The model is shown a node's signature, contract, types and the `aap:caps` package *without its worlds* (the node's own world is half the answer), and writes its own world, so that an ungranted import is expressible. `gate` is `interfaces.py`, unchanged. The report never states a catch rate where there were no attempts, keeps gate catches, ambient calls and declared-only imports apart, and fails the build if a hand-written body does not pass clean. The `authorised` arm was **added after the pilot's first two arms were read**; say so wherever it is cited.
- **An adapter binds an interface whole.** The pilot's first twelve `Heartbeat` trials failed because the host adapter bound `http-client` with only `get`, and the models were told they had imported an ungranted capability. Those trials are voided and kept (`poc/generation/voided/`). A test now holds every adapter to every function of every interface it links; the host raises `IncompleteHostBinding` for this case; the pipeline stops on a harness fault rather than charge it to the model.
- **Do not edit `poc/`, `scripts/` or `caps.wit` while a generation run is in progress.** The contract and run steps execute in child processes that import the working tree; a half-finished edit is recorded as the model's failure.
- **`make wasm` rebuilds every artifact, and an unchanged crate can still differ in bytes.** Commit only the components whose crates changed and `git checkout` the rest: the nine Paper 2 components are its evidence as built.
- **The inspector also shows the service** (`/api/feed/…` routes, `ui/components/FeedPanel.tsx`): still an inspector, not an editor, and still a mention in a paper, never a section.

### Strengthening the generation evidence (`openspec/changes/strengthen-generation-evidence`)

Built 27 October 2026, up to the registered run. **Every session working on it starts the feed recorder first** (the command is in that change's `tasks.md`, task 0.3).

- **The registered replication** (`poc/generation/registration.py`, `registration.json`): 2,250 trials over pretexts P0–P6 and a rule-withheld condition. The registration holds the models by full ID, the hash of every task, and **one primary outcome** (first-attempt reach) with **one confirmatory test** (Fisher exact, P5 vs P0). `harness registered` refuses to run it if the file is uncommitted or edited, if a task hash drifts, if a model resolves to another ID, if the tree it imports is dirty (checked before every trial), or if the hand-written control fails. Do not start it before the author has approved the pretexts (task 1.4a). Call it pre-registration inside one repository, never a registry entry. **Never pool** its trials with the earlier ones: the report keeps them apart, and a test holds that.
- **The "2, 39, 63" authorised spread is any-attempt gate catches.** On the registered definition the post-hoc arm is 1/37/59 of 75. A test pins both, and the report labels each.
- **The differential step** (`poc/generation/differential.py`) compares green bodies with the hand-written ones on the contract's inputs. It uses a model stand-in that never reads the prompt. The result is information, never a gate, and "equal" means equal on those inputs (one to four, for some nodes), not equivalence. Results live beside the runs, in `poc/generation/differential/`.
- **Recorder and replay** (`poc/feeds/archive.py`, `poc.serve --replay`): the recorder archives raw feeds into `var/archive/`, without calling a model. A replay runs the service over the archive with an injected clock, into its own `var/replays/…`, and never into the live `var/`. `dist/evaluation-feed.md` keeps **live operation, the recording period and replayed history** in three sections. **A replay is never operation**: scheduling claims come from live ticks only.
- **Everything long-running lowers its own priority** (`poc/polite.py`: nice 19 plus macOS background QoS, inherited by children; checked, and tested). Use `--no-nice` only on an idle machine.
- **AgentDojo:** banking expresses as graphs, but a benchmark built from hand-written graphs would measure oracle plans (`docs/agentdojo-spike.md`). A comparable number needs a prompt-to-graph planner first.

The toolchain is **not** the Phase 1 language: it implements no noninterference proof, no soundness argument, and neither a graded nor a decentralised-label lattice (see the paper's research agenda). The sandbox tier makes capability confinement unforgeable *at the WASM boundary* for the nodes ported to it, but not at the memory level (CHERI) and not for host-tier nodes. Typing the boundary closes ambient authority and marshalling ambiguity; it does **not** close the free-text residual (adversarial data in a *permitted* field still reaches the tool-capable node — a test asserts this on the confined tier on purpose, so stronger enforcement is not misread as a stronger claim). It is early evidence that the graph-level analyses and capability confinement are implementable with modest tooling.

## Spec-driven development (OpenSpec)

Work on this repo is driven through **OpenSpec** (`openspec/`). Read `openspec/AGENTS.md` before planning changes. Non-trivial work gets a change proposal (`openspec/changes/<id>/` with `proposal.md`, `tasks.md`, optional `design.md`, and spec deltas), validated with `openspec validate <id> --strict`, and approved before implementation. This dogfoods the proposal's own thesis: structured intent as the primary artifact.

## Version control

This repo uses **trunk-based development**: work lands on `main`. **Never create a branch unless explicitly asked to.** Commit directly to `main`.

**Commit as you go.** Don't wait to be asked. When a change reaches a coherent, self-contained state and the gate is green (`make build` / the pre-commit hooks pass), commit it with a clear message rather than accumulating a large uncommitted working tree. Prefer several focused commits over one sprawling one; each commit should leave `main` buildable. This is the default — the standing instruction to "commit only when the user asks" does **not** apply here.

**When to hold off and check in first:** if the work involves a decision the user should weigh in on before it's recorded in history — an ambiguous requirement, a non-obvious design trade-off, something hard to reverse, or anything outward-facing (pushing, publishing, posting) — surface it and let the user decide instead of committing past it. Approval to commit routine progress is not approval to push or publish; those still need an explicit ask.

## Build

```sh
make build        # Validate graphs, run tests, guard the freeze, build the whole corpus (PDF + md + HTML per paper) + grammar card + evaluation artifact
make evaluation   # Run the demonstrator's evidence and emit dist/evaluation.md (needs the `poc` group; pinned verdicts fail the build on divergence)
make evaluation-feed  # The feed-triage service's evidence → dist/evaluation-feed.{md,json} (pinned; serves hostile feeds from 127.0.0.1; calls no model)
make generation   # Render the generation experiment from committed results → dist/generation.{md,json} (stdlib-only; calls no model, builds no crate)
make test         # Run the type-parser, graph-validator, and runtime unit tests (pytest)
make wasm         # Rebuild the sandbox-tier .wasm artifacts from Rust (needs a Rust toolchain)
make ui           # Opt-in: run the graph inspector (execution API + Next.js dev server; needs Node)
make ui-check     # Opt-in: typecheck + production build of the inspector UI
make ui-e2e       # Opt-in: Playwright e2e of the paper-facing claims; regenerates ui/screenshots/
make api          # Opt-in: the inspector's execution API alone (http://127.0.0.1:8123)
make clean        # Remove dist/
```

Requires: [Typst](https://typst.app/), [Pandoc](https://pandoc.org/) (with citeproc), Python 3 via [uv](https://docs.astral.sh/uv/). All three are present and working in the current environment (typst 0.15, pandoc 3.11, uv 0.12). Toolchain upgrades change rendered output without any source change — pandoc 3.11 parses a centred prose block as a `Div`, which the Lua filter dropped until it learned to keep one (opt-in per paper via `-M keep-centred-notes=true`); pandoc 3.11 also stopped attaching a heading's `<sec:…>` label to the heading, emitting it as an empty anchor paragraph after it, so every `@sec:` reference in the Markdown/HTML rendered as its bare label (`§open`) until the filter learned to re-attach it (September 2026, now pinned by `tests/test_resolve_crossrefs.py`); and typst 0.15 re-formats some bibliography entries relative to the PDF published on Zenodo. That drift is why Paper 1 is now served from its published artifacts rather than rebuilt.
