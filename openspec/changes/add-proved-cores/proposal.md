# Proved node cores, with call bounds, behind a hardened gate

> **Status: proposed, not approved.** It was written on 18 November 2026, after the author
> accepted spikes S3 and S4's recommendation (`explore-specified-architecture`,
> archived). Nothing is implemented before task 0.1 and the answers to `design.md`'s
> open questions.

## Why

A node's contract is checked at run time on the inputs it happens to meet. A proof can
say it holds for every input, including every reply a model can give, because the model
is a universally quantified argument.

S3 and S4 (`spikes/specified-architecture/s3/`, `s4/`, each with a `RESULT.md`) showed
the route works on this artifact:
- **The route:** a pure Rust core pulled out of each node body, translated by
  Charon/Aeneas, proved in Lean against statements the gate owns.
- **By hand:** three nodes proved.
  - One, GenerateResponse's tool loop, is proved for every `Host`, that is, every model
    and knowledge base.
  - It carries a call bound (at most 3 model calls and 3 lookups). The unchanged shipped
    component never exceeded it on 81 reply scripts.
- **The pilot:** models reached gate-accepted proofs in 20 of 29 counted trials (Opus
  13/14, Sonnet 7/15), always after repairing from the gate's refusal. All 20 pass the
  hardened gate.

Verification found where the risk sits:
- **The first gate could be fooled.** A proof file redefined `#print axioms`, and a
  proof file runs code at build time.
- **The hardened gate** builds in a sandbox, pins the compiled statements, and audits in
  a separate process (exact statement type, an axiom walk, a kernel replay).
- **Every weakness left is in a statement:**
  - one admits an empty summary;
  - one claims an order its `Prop` does not state;
  - `respond_spec` omits the tool-scope property, since a lookup carries no tool name.

## What Changes

- **A proved core per ported node**, beside its confined component, starting with the
  three spiked nodes, and the `run` shell tied to the core by a differential test.
- **Statements generated by the gate from the graph**: from a node's contract, its
  capability clause (every effect within the granted scope, with the tool or payee in the
  effect), and its declared call budget (S4's bound as a conjunct). They are pinned by
  hash.
  - **`respond_spec` is strengthened** to "every lookup's tool is the granted one", with
    `Effect::Lookup` carrying the tool.
  - **The pinned statement's prose is generated from the same source** as its `Prop`, so
    the two cannot disagree (the docstring gap S3 found).
- **The hardened gate as a build step for proved nodes**, with Lean, Aeneas and Charon in
  their own optional toolchain, like `make wasm`. Built artifacts are committed, so the
  build verifies without the prover only where the design decides it may (open question
  2).
- **A proved call bound narrows the node's `Calls` budget** (`add-resource-budgets`),
  never the reverse.
- **A generation run** under the registered-run discipline, if the author wants agent
  proofs as evidence (open question 3).

## Impact

- **Code:** `poc/sandbox/rust/` (cores split from bodies), a `proofs/` tree, the gate and
  audit moved from the spike, and `Makefile` (an opt-in `make proofs`).
- **Depends on** `add-resource-budgets` for the call-bound conjunct. The rest is
  independent.
- **Paper 2's figures must not move.** The nine Paper 2 components are evidence as built.
  Splitting their crates rebuilds them, so the derivation rows are re-run, and any byte
  change is a finding for the author.
- **Evidence for a later paper** on specified architecture. That paper is proposed when
  this change and its two siblings land, not now.
- **New capability:** `proved-cores`.
- **End condition:** the tasks are done, `make build` is green, two verifying subagents
  have reported, and the change is archived.
